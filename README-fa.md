# TWP-CF — پروکسی وب تلگرام روی Cloudflare Workers

یک پروکسی وب تلگرام خودکفا (self-contained) که روی Cloudflare Workers اجرا می‌شود و با کمک یک Durable Object ترافیک بین کلاینت تلگرام و دیتاسنترهای تلگرام را از طریق MTProto رله می‌کند. می‌توانید آن را مستقیماً از مرورگر با استقراردهنده‌ی استاتیک همین مخزن مستقر کنید، یا اگر حرفه‌ای هستید، با `wrangler` دستی.

**معماری:**

```
کلاینت تلگرام → HTTPS → Worker → WebSocket → Durable Object → TCP → DC تلگرام
```

## 🚀 شروع سریع

مسیری که مناسب شماست را انتخاب کنید:

### 🟢 مسیر A — استقرار با صفحه‌ی استاتیک مرورگر (سریع‌ترین و توصیه‌شده)

این مخزن یک فایل HTML تکی به نام [`index.html`](index.html) دارد که استقرار پروکسی را **مستقیماً از مرورگر شما** روی اکانت Cloudflare انجام می‌دهد. این صفحه روی GitHub Pages اجرا می‌شود: بدون ترمینال، بدون سرور و بدون مرحله‌ی build. توکن API شما فقط در حافظه‌ی مرورگر می‌ماند و هیچ‌جا ذخیره نمی‌شود؛ فقط به API خود Cloudflare فرستاده می‌شود.

**گام‌به‌گام:**

1. **مخزن را در گیت‌هاب باز کنید:** [github.com/MHDLabs/TWP-CF](https://github.com/MHDLabs/TWP-CF).
2. **فعال کردن GitHub Pages** (فقط یک بار): به **Settings → Pages** بروید، در بخش Source گزینه‌ی **Deploy from a branch** را انتخاب کنید، شاخه‌ی `main` و مسیر `/ (root)` را بگذارید و ذخیره کنید.
   > صرف اضافه شدن `index.html` به گیت، Pages فعال نمی‌شود — فعال‌سازی دستی از همین بخش Settings لازم است.
3. صبر کنید Pages ساخته شود، سپس صفحه‌ی منتشرشده را باز کنید:
   `https://mhdlabs.github.io/TWP-CF/`
   > این ساختار آدرس، قالب استاندارد GitHub Pages برای این مخزن است. اگر Pages هنوز فعال نشده باشد، آدرس 404 می‌دهد — مرحله‌ی ۲ را کامل کنید. این پروژه تضمین نمی‌کند که Pages هم‌اکنون منتشر شده باشد.
4. **ساخت توکن API کلودفلر:** در صفحه لینک **Create token** هست که دسترسی‌های لازم (Account Settings Read، Workers Scripts Edit، Workers Subdomain Edit) را از پیش تنظیم می‌کند. ساخت توکن را در داشبورد Cloudflare تمام کنید و کپی بگیرید.
5. **توکن را در فیلد رمزعبور صفحه بچسبانید** و **Verify Access** را بزنید.
6. **اکانت را انتخاب کنید** (اگر توکن چند اکانت دارد) و در صورت تمایل نام Worker را تعیین کنید. فیلد secret پروکسی را خالی بگذارید تا خودکار ساخته شود.
7. **Deploy Worker** را بزنید و تا پایان مراحل پیشرفت صبر کنید.
8. **نتایج را همان لحظه ذخیره کنید**: استقراردهنده **رمز پروکسی** و **توکن مدیریت** را فقط یک بار نشان می‌دهد. هر دو را جایی امن نگه دارید — Cloudflare اجازه نمی‌دهد secret را بعداً بخوانید.
9. **لینک پروکسی تلگرام را کپی کنید** و روی دستگاهی که تلگرام دارد باز کنید، یا سرور/پورت/secret را دستی اضافه کنید (بخش پایین).
10. **استقرار را بررسی کنید**: دکمه‌ی **Open Worker** را بزنید یا `https://<worker>.<subdomain>.workers.dev/healthz` را باز کنید — باید پاسخ JSON کوچک `ok` بگیرید.
11. **پروکسی را در تلگرام اضافه کنید** با لینک نمایش‌داده‌شده در بخش نتیجه.
12. **وقتی همه‌چیز را ذخیره کردید، صفحه‌ی عمومی را غیرفعال کنید**: آدرس ریشه‌ی Worker را در مرورگر باز کنید، از کنترل «پنهان کردن این صفحه» استفاده کنید و توکن مدیریت را وارد کنید. جزئیات در بخش [صفحه‌ی عمومی و غیرفعال کردن](#صفحه-ی-عمومی-و-غیرفعال-کردن).

> ⚠️ **محدودیت CORS — حتماً بخوانید**: طبق بررسی حاضر، `api.cloudflare.com` برای origin هایی غیر از داشبورد خود Cloudflare هدر `Access-Control-Allow-Origin` برنمی‌گرداند (پیش‌پرواز `OPTIONS` با HTTP 400 و کد 7001 و بدون هدر CORS پاسخ می‌دهد). یعنی مرورگر روی GitHub Pages معمولاً **اجازه‌ی فراخوانی مستقیم API کلودفلر را ندارد** و استقراردهنده به‌جای جعل موفقیت، خطای CORS صریح نشان می‌دهد. این محدودیت سمت Cloudflare و تأییدشده است، باگ `index.html` نیست و از یک صفحه‌ی استاتیک قابل رفع نیست (هیچ بک‌اند یا پروکسی‌ای اضافه نشده). اگر با این خطا مواجه شدید، از **مسیر B** (wrangler) استفاده کنید — دقیقاً همین فراخوانی‌های API را از دستگاه خودتان انجام می‌دهد که CORS در آن معنا ندارد.

### 🔵 مسیر B — استقرار دستی با wrangler (حرفه‌ای)

پیش‌نیازها: [Node.js](https://nodejs.org/) نسخه ۱۸ به بالا و یک اکانت Cloudflare.

1. **کلون یا دانلود پروژه:**

   ```sh
   git clone https://github.com/MHDLabs/TWP-CF.git twp-cf
   cd twp-cf
   ```

2. **نصب وابستگی‌ها:**

   ```sh
   npm install
   ```

3. **دو secret مستقل بسازید:**

   ```sh
   openssl rand -hex 16   # → PROXY_SECRET (۳۲ کاراکتر hex)
   openssl rand -hex 32   # → PANEL_ADMIN_TOKEN (۶۴ کاراکتر hex)
   ```

   هر دو مقدار را جایی امن نگه دارید.

4. **ورود به Cloudflare:**

   ```sh
   npx wrangler login
   ```

5. **تعریف هر دو secret** (مقدار مربوطه را هنگام پرسش وارد کنید):

   ```sh
   npx wrangler secret put PROXY_SECRET
   npx wrangler secret put PANEL_ADMIN_TOKEN
   ```

6. **استقرار:**

   ```sh
   npm run deploy
   ```

   فایل `wrangler.toml` از قبل binding های Durable Object برای `SESSIONS` و `PANEL_SETTINGS`، مهاجرت‌های SQLite و متغیرهای متنی را تعریف کرده است — دستور deploy همه‌چیز را می‌سازد.

7. **فعال‌سازی workers.dev** در داشبورد Cloudflare (Workers & Pages → Worker شما → *Settings* → *Workers.dev*) تا پروکسی در آدرس `https://<worker-name>.<subdomain>.workers.dev` در دسترس باشد.

## 📱 اضافه کردن پروکسی به تلگرام (مرحله‌ی دستی)

Cloudflare میزبانی پروکسی را انجام می‌دهد — اضافه کردنش به تلگرام را **باید دستی روی دستگاه خودتان** انجام دهید:

1. **لینک شخصی پروکسی‌تان را بسازید** — دو مقدار زیر را جایگزین کنید:

   ```
   https://t.me/webproxy?server=<worker-host>&secret=<PROXY_SECRET>
   ```

   مثال (مقادیر شما متفاوت خواهد بود 😉):

   ```
   https://t.me/webproxy?server=twp-cf.my-subdomain.workers.dev&secret=0123456789abcdef0123456789abcdef
   ```

2. **لینک را روی دستگاهی که تلگرام روی آن نصب است باز کنید** — تلگرام خودش پیشنهاد اضافه کردن پروکسی را می‌دهد. تمام 🎉

3. **یا دستی اضافه کنید** داخل تلگرام:
   - **اندروید:** Settings → Data and Storage → Proxy → ➕ Add proxy → نوع: **MTProto**
   - **دسکتاپ:** Settings → Advanced → Proxy → Add proxy → نوع: **MTProto**
   - **سرور:** `twp-cf.my-subdomain.workers.dev` · **پورت:** `443` · **secret:** همان `PROXY_SECRET` شما

> 💡 باز کردن `https://<worker-host>/` در مرورگر هم صفحه‌ی آماده‌ای با لینک پروکسی شما نشان می‌دهد. یادتان باشد بعد از راه‌اندازی [آن را غیرفعال کنید](#صفحه-ی-عمومی-و-غیرفعال-کردن) — این صفحه رمز پروکسی را در اختیار هر بازدیدکننده‌ای می‌گذارد.

## صفحه‌ی عمومی و غیرفعال کردن

### این صفحه چه چیزی نشان می‌دهد — و چرا خصوصی نیست

به‌صورت پیش‌فرض، باز کردن آدرس ریشه‌ی Worker (`/`) یک صفحه‌ی کوچک با سرور، پورت، **رمز پروکسی** و لینک آماده‌ی تلگرام نشان می‌دهد. برای راه‌اندازی راحت است، اما **هر کسی که بتواند این آدرس را حدس بزند یا پیدا کند، رمز پروکسی را می‌خواند** و می‌تواند از پروکسی شما استفاده کند. تا وقتی صفحه را غیرفعال نکرده‌اید، آن را عمومی در نظر بگیرید.

### غیرفعال کردن صفحه

صفحه یک کنترل ساده‌ی **پنهان کردن این صفحه** دارد. این کنترل **توکن مدیریت** (`PANEL_ADMIN_TOKEN`) را می‌خواهد، قبل از اجرا تأیید می‌گیرد و یک endpoint اختصاصی و احرازهویت‌شده را صدا می‌زند (`POST /api/v1/panel/disable`). بعد از غیرفعال شدن موفق:

- بازدیدهای معمولی از `/` پاسخ `404` ساده می‌گیرند (همان پاسخ camouflage که برای همه‌ی مسیرهای ناشناخته استفاده می‌شود) — بدون رمز، بدون لینک پروکسی و بدون کنترل مدیریتی.
- **خود پروکسی کار می‌کند**: لینک‌های معتبر تلگرام، مسیرهای session/WebSocket و `/healthz` دست‌نخورده می‌مانند.
 - وضعیت غیرفعال بودن **به‌صورت دائمی سمت سرور** در یک Durable Object اختصاصی (`PanelSettings`) ذخیره می‌شود و با بازدیدکننده‌ی جدید، دستگاه دیگر یا ری‌استارت Worker از بین نمی‌رود.

### سه اعتبارنامه‌ی متفاوت

| اعتبارنامه | چیست | کجا نگهداری می‌شود |
| --- | --- | --- |
| `PROXY_SECRET` | احراز هویت اتصال‌های MTProxy (۳۲ کاراکتر hex) | secret در Cloudflare |
| `PANEL_ADMIN_TOKEN` | احراز هویت کنترل غیرفعال‌سازی (حداقل ۳۲ بایت تصادفی) | secret در Cloudflare |
| توکن API کلودفلر | فقط برای آپلود کد توسط استقراردهنده/wrangler | متعلق به شما، هنگام استقرار وارد می‌شود |

این سه مستقل‌اند. صفحه‌ی عمومی هرگز `PANEL_ADMIN_TOKEN` را نشان نمی‌دهد و عوض کردن `PROXY_SECRET` صفحه‌ی غیرفعال‌شده را باز نمی‌گرداند.

### بازیابی دسترسی — توکن مدیریت را فراموش کردم

عمداً **دکمه‌ی عمومی برای فعال کردن دوباره وجود ندارد**. برای بازگرداندن صفحه، کافی است secret را در داشبورد Cloudflare با مقدار جدید جایگزین کنید:

1. به **Workers & Pages → Worker شما → Settings → Variables and Secrets** بروید.
2. `PANEL_ADMIN_TOKEN` را در بخش Secret پیدا کنید، **Edit** را بزنید و یک مقدار امن جدید بچسبانید (مثلاً `openssl rand -hex 32`).
3. ذخیره کنید، سپس آدرس ریشه‌ی Worker را باز کنید — صفحه خودبه‌خود برمی‌گردد.

شیوه‌ی کار: هنگام غیرفعال شدن، Worker فقط یک **اثر انگشت** ( fingerprint) از توکن مدیریت با الگوریتم SHA-256 ذخیره می‌کند — نه خود توکن را. در هر بازدید، اثر انگشت secret *فعلی* با مقدار ذخیره‌شده مقایسه می‌شود؛ اگر متفاوت باشد یعنی مالک توکن را عوض کرده و وضعیت غیرفعال پاک می‌شود. اگر خواندن ذخیره‌گاه وضعیت ممکن نباشد، صفحه پنهان می‌ماند (fail closed) — اما پروکسی کار می‌کند.

### نکات چرخش (rotation) رمزها

- secretی که یک بار به Cloudflare داده‌اید **قابل بازخوانی نیست** — به همین دلیل استقراردهنده آن را فقط یک بار نشان می‌دهد. اگر `PROXY_SECRET` را گم کردید، با `wrangler secret put PROXY_SECRET` مقدار جدید بسازید و تنظیمات پروکسی تلگرام را به‌روز کنید.
- **پنهان کردن صفحه یعنی اشتراک‌گذاری قبلی لغو شود؟ خیر.** هر کسی که موقع باز بودن صفحه آن را دیده باشد، ممکن است رمز پروکسی را کپی کرده باشد. اگر صفحه مدتی عمومی بود، بعد از غیرفعال کردنش `PROXY_SECRET` را هم عوض کنید.
- اگر شک دارید `PANEL_ADMIN_TOKEN` لو رفته، حداقل یک بار آن را عوض کنید؛ چرخش توکن صفحه‌ی عمومی را هم برمی‌گرداند (بازیابی بالا)، پس در صورت لزوم دوباره غیرفعالش کنید.

## به‌روزرسانی پروکسی

به‌روزرسانی دستی در هر زمان: `npm run deploy` از یک کلون تازه. استقراردهنده‌ی استاتیک هم می‌تواند با همان نام Worker، روی استقرار قبلی دوباره deploy کند.

## اجزای پروژه

| فایل | کاربرد |
| --- | --- |
| `index.html` | استقراردهنده‌ی استاتیک مرورگری برای GitHub Pages (فایل‌های زمان اجرا را از همین مخزن می‌گیرد و مستقیماً با API کلودفلر کار می‌کند) |
| `index.js` | نقطه‌ی ورود Worker: روتینگ HTTP، احراز هویت، توکن‌های bootstrap/session، تابع `publicPage`، تابع `camouflage`، endpoint غیرفعال‌سازی پنل و کلاس‌های Durable Object با نام‌های `WebProxySession` و `PanelSettings` |
| `session.js` | کلاس `RelaySession`: رله‌ی فریم‌ها بین WebSocket و TCP تلگرام، چرخه‌ی عمر استریم‌ها، flow control و محدودیت‌های صف |
| `mtproxy.js` | پیاده‌سازی AES-CTR، handshake های MTProto سمت کلاینت و تلگرام، لیست آدرس‌های DC تلگرام، پارس `PROXY_SECRET` |
| `protocol.js` | تعریف فریم‌ها (`OPEN`، `DATA`، `CLOSE`، `WINDOW`، …)، توابع `encodeFrame`/`parseFrames` و ثابت‌های پروکسی |
| `bridge.js` | صفحه‌ی HTML مخصوص bridge که در iframe کلاینت تلگرام بارگذاری می‌شود و پورت اپلیکیشن را به WebSocket سرور وصل می‌کند |

## نحوه‌ی کار پروکسی

کلاینت تلگرام ابتدا صفحه‌ی `bridge` را در iframe باز می‌کند. صفحه‌ی bridge با یک درخواست `POST` کوتاه به `/api/v1/session` یک bootstrap token معتبر می‌گیرد و یک فریم `WELCOME` دریافت می‌کند. سپس از طریق WebSocket به مسیر `/api/v1/ws` متصل می‌شود. هر فریم داده توسط Worker به یک Durable Object با نام `WebProxySession` فوروارد می‌شود؛ همان‌جا handshake مخصوص MTProxy با `PROXY_SECRET` انجام می‌شود و یک اتصال TCP مستقیم به یکی از دیتاسنترهای تلگرام برقرار می‌گردد. ترافیک در هر دو جهت با AES-CTR رمزگذاری شده و با استفاده از فریم‌های `WINDOW` مدیریت flow control می‌شود. صفحه‌ی ریشه (مگر غیرفعال شده باشد) صفحه‌ی عمومی اطلاعات را نشان می‌دهد و سایر مسیرها با پاسخ `404` معمولی پنهان می‌شوند (`camouflage`).

## متغیرهای محیطی و secret ها

| نام | نوع | اجباری | پیش‌فرض | توضیح |
| --- | --- | --- | --- | --- |
| `PROXY_SECRET` | secret | **بله** | — | ۳۲ کاراکتر hex، یا `dd` + ۳۲ کاراکتر hex. با `wrangler secret put PROXY_SECRET` ست می‌شود |
| `PANEL_ADMIN_TOKEN` | secret | خیر* | — | حداقل ۳۲ بایت تصادفی (مثلاً `openssl rand -hex 32`). کنترل «پنهان کردن این صفحه» را فعال می‌کند. با `wrangler secret put PANEL_ADMIN_TOKEN` |
| `SESSION_TTL_SECONDS` | var | خیر | `300` | عمر توکن session (بین ۳۰ تا ۶۰۰ ثانیه) |
| `MAX_STREAMS` | var | خیر | `64` | حداکثر تعداد استریم همزمان در هر session (بین ۱ تا ۱۲۸) |
| `DIAGNOSTICS` | var | خیر | `0` | مقدار `1` لاگ‌های مفصل رله را فعال می‌کند |

\* بدون `PANEL_ADMIN_TOKEN` صفحه‌ی اطلاعات همیشه نمایش داده می‌شود و کنترل غیرفعال‌سازی ندارد — ولی پروکسی کار می‌کند. برای توانایی پنهان کردن صفحه، این secret را ست کنید.

متغیرها در فایل `wrangler.toml` و بخش `[vars]` تعریف شده‌اند؛ دو secret باید جداگانه ثبت شوند.

## نکات امنیتی

- **`PROXY_SECRET` را با کسی به اشتراک نگذارید** — هر کسی که این کلید را داشته باشد می‌تواند از پروکسی شما استفاده کند.
- **کلیدها را در Git commit نکنید** — فایل‌های `.dev.vars` و `.env` در `.gitignore` هستند؛ secret ها فقط در secret store کلادفلر نگهداری می‌شوند.
- **بعد از راه‌اندازی، صفحه‌ی عمومی را غیرفعال کنید** — این صفحه رمز پروکسی را در اختیار هر بازدیدکننده‌ای می‌گذارد.
- **توکن مدیریت را نمی‌توان بازخوانی کرد** — Cloudflare آن را فقط برای استفاده‌ی بعدی در دسترس نگه می‌دارد؛ بازیابی با جایگزینی انجام می‌شود.
- **ترافیک از Cloudflare عبور می‌کند** — Worker ترافیک تلگرام شما را بین کلاینت و دیتاسنترهای تلگرام رله می‌کند.

## توسعه‌ی محلی

```sh
cp .dev.vars.example .dev.vars   # سپس PROXY_SECRET و PANEL_ADMIN_TOKEN را ویرایش کنید
npm run dev
```
